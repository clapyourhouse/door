# Door Travel 設計(2026-11-14 版)

旧版(人が回答する東京相談を中心にした案)と、引き継ぎメモ(AIガイドのみ)を統合した設計。決定済みの事項と未決事項を分けて記載する。

## 1. プロダクト方針

訪日旅行者が日本各地を探索し、旅先で気になったことをその場で聞けるアプリ。AIだけではChatGPTで足りるため、**AIが即答し、有料パスでは人(北村)にも相談できる**ことを価値にする。

- 探索先は**日本各地の主要都市**。初期は、東京・京都・大阪・札幌など訪日客の定番都市から数地点(現在の試作は浅草・祇園・道頓堀・札幌)。東京は複数エリア(渋谷・新宿・浅草など)に分けてもよい。その後、福岡・名古屋・広島・那覇などへ広げる。
- 元のDoorのデザインと操作感を使う(扉の演出、全画面Street View、街名HUD、チャットパネル)。
- UIは日本語と英語。**全世界配布**(訪日客は自国のGoogle Playから探すため)。

## 2. ユーザー体験

1. 「扉を開く」で日本のどこかの主要都市へ飛ぶ。
2. 画面内のStreet Viewで見渡す。同時に、そのエリアのAIガイドが挨拶してチャットが始まる。
3. 到着先の質問と、旅行全般の相談(例:雨で午後の予定が崩れた)ができる。
4. 「移動する」で別エリアへ。会話は新しいエリアのガイドで始まる。
5. 無料枠の後に購入案内。購入後は「人に聞く」ボタンで北村に引き継げる。

## 3. 料金(決定済み)

| 項目 | 内容 |
|---|---|
| 探索(扉・移動・Street View) | 無料 |
| AIへの質問 | 無料枠(街を移動しても同じ枠)。**10回に決定(2026-11-15、本人)**。環境変数 `FREE_QUESTION_LIMIT`=10。先行ユーザー段階で購入案内までの反応を測り、必要なら再検討 |
| 有料パス | **7日間 ¥980 / US$6.99**(言語で出し分け)、一度の支払い、自動更新なし。街を移動しても継続 |
| パス中のAI質問上限 | **1日100回まで**(実質使い放題。AI費用と悪用の安全弁。環境変数 `PASS_DAILY_LIMIT`) |
| パス中の「人に聞く」 | 利用可。**件数の上限は未決定** |
| 人の返信の目安 | **日本時間10〜18時、通常は数時間以内**(アプリ内に明記。担当者のオンライン/オフラインは管理画面の手動スイッチで表示。試験期間は北村さんが対応し、運用が見えたらアルバイトを検討) |

購入案内は、無料の回答を体験した後に出す。測るもの: 回答で次の行動を決められたか、旅行中の再質問、パス購入率、人への引き継ぎ率、購入者あたりの対応分数。

## 4. アーキテクチャ

- **アプリ**: Capacitor 8(Androidを先行、iOSは同一コード)。`app/www` をWebViewで表示。appIdは仮(`jp.sdx.door.travel`)で、Play登録前に確定する(確定後は変更不可)。
- **サーバー(Supabase)**
  - 匿名認証(ログインなし。端末ごとにユーザーを持つ)
  - Edge Function `chat`: 無料枠・パス・1日上限を判定し、OpenAIを呼ぶ。キーはサーバーの環境変数のみ
  - Edge Function `handoff`: 「人に聞く」を保存し、北村へ通知
  - Edge Function `verify-purchase`: Google Play Developer APIで購入を検証し、7日分を付与
  - DB: `devices`, `usage`(質問回数), `passes`(期限・購入トークン), `handoffs`(質問・返信・状態), `cities`(街の一覧・座標・ガイドの人格)
- **簡易管理画面**: 北村が引き継ぎを一覧し、返信する。返信はアプリのチャットに表示される。
- **街のデータ**: サーバー側の `cities` から取得し、街の追加にアプリ更新を要さない。
- **Street View**: Maps Embed APIを画面内に埋め込む。キーは配信元とAPIを制限。Capacitor WebViewの配信元(`https://localhost`)で制限が効くか、実機で確認する。
- **AI回答**: 質問の言語(日英)で返す。店舗・交通の最新状況は、確認時刻と出典を示す。出力上限とレート制限あり。

## 5. 課金(Google Play)

- アプリ内のデジタルな利用権のため、Google Play決済を使う。
- 7日パスは消費型の都度購入として設計し、サーバーで検証してから7日分を付与する。購入の検証はSupabaseで自前実装。
- **要確認**: (a) 人の回答を含むパスのPlay決済上の扱い、(b) 再インストール時のパス復元方法、(c) 消費型と、期間指定のプリペイド型の選択。

- 先にwebで公開し、広告(Meta・少額)と先行インフルエンサー10名で最初の100人を集める。Androidのクローズドテストは並行して進め、web利用者のアンケートでテスターを募る。

- 計測は `events` テーブル(扉を開く・最初の質問・パス案内表示・興味あり・購入ボタン・人に聞く・アンケート)。流入元は `?ref=名前` と `utm_campaign`。
