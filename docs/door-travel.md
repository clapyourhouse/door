# Door Travel

## プロダクト方針

初めて東京を訪れる英語話者が、移動・宿泊エリア・旅程の変更で判断に迷ったとき、次の行動を決められるようにする。最初は東京の相談を北村が担当する。他都市のAIガイドは、東京で質問の種類と回答品質が見えてから拡張する。

北村と訪日予定者2人で、実際の旅行に関する質問を持ち込み、回答によって何を決めたかを確認する。北村の検証は運営側も兼ねるため、訪日予定者2人の実際の行動を別に記録する。旅行者が自力検索で解決した場合も理由を聞く。

無料テストの後、7日間1,000円の仮説を試す。質問は随時受付とし、人による回答時間は案内に明記する。購入率、人への引き継ぎ率、購入者あたりの対応分数、回答で行動が決まった割合を記録する。店舗・交通の最新状況を答える際は、確認時刻と出典を示す。

GTMは訪日予定者への直接テストから始める。質問から行動までの実例が取れたら、訪日旅行クリエイターにデモを依頼する。Meta広告は相談完了まで測れる状態で小さく検証する。

## 実装と公開

旧Web試作はルートに残し、配布用の共通UIは app/www に置く。CapacitorでAndroidを先行し、同じUIをiOSでも使う。appIdは仮。最初のPlay登録前に公開名義と合わせて確定する。

現在の実装は質問下書きの端末保存と削除。相談受付・返信・AI・決済は未実装。公開用の最初の機能は、質問を送信し、運営が回答し、旅行者が返信を確認できること。旧HTMLのブラウザからのAI直接呼び出しは移植しない。

Android環境を用意したら app で npm install、npm run android:add、npm run android:sync を実行する。Android Studioで実機確認し、署名済みAABを生成する。Play Consoleでアプリ情報、プライバシー、データセーフティ、テスト配信を設定する。ストア決済方式は有料化の実装前に確認する。
